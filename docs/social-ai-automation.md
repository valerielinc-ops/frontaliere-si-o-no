# Social publishing with Codex

The social publishers use Codex for reusable monthly hooks and calls to action.
The existing publishers continue to select the source posts, verify the
underlying facts, render media, apply canonical tracking links, deduplicate,
and deliver through the existing platform API or browser robot.

## Automated flow

1. The scheduled workflow runs on the first day of each month and invokes
   Codex once for the complete channel matrix. The first pack is generated by
   dispatching this workflow during rollout; publishers otherwise retain
   their deterministic copy until a validated pack reaches `main`.
2. The Codex job receives editorial instructions, a minimized 72-hour Instagram
   copy-performance brief, a minimized 30-day GA4 social-link attribution brief,
   and CODEX_AUTH_JSON. The GA4 query uses the Firebase service account only in
   a separate read-only collection step; Codex receives aggregate sessions,
   post-click website engagement rates, channel/kind, copy slot, and template
   IDs, never credentials, post text, media IDs, URLs, or user-level data. GA4 groups
   require ten sessions before descriptive use; Instagram groups require three
   observations. Both sources are descriptive and never choose winners or
   change experiment decisions.
3. A separate job validates the exact JSON schema and rejects missing slots,
   duplicate hooks or CTAs, long copy, links, handles, markup, placeholders,
   numeric claims, CTAs without exactly one recognized imperative action, and
   Instagram CTAs that do not match their declared objective.
   Instagram has three copy variants for each of its `share`, `save`, and
   `conversation` objectives. Facebook jobs have twelve hooks/CTAs for the
   existing 24-post schedule. Only then does the workflow open a protected PR
   for `data/social-copy-packs/current.json`; required checks and Codex review
   must pass before GitHub's native auto-merge admits the pack to `main`.
4. Publishers assign templates deterministically from the channel, format,
   content identity, and (for Instagram) the existing creative objective.
   Retries keep the same copy; Telegram border copy is keyed to the digest's
   week window.
5. Instagram applies the same generated hook and objective-matched CTA to its
   caption and rendered cover/closing card. Its publisher always retains a
   link-in-bio destination note. TikTok receives its hook on the cover and
   keeps the link-in-bio destination in the caption; generated answer-video
   CTAs also appear on the final card. Facebook, LinkedIn, and Telegram keep
   their canonical destinations in the existing publishers.
6. A missing, stale, malformed, or invalid pack falls back to each publisher's
   existing deterministic copy. Generation failures do not block posting.
7. Where a publisher has an existing ledger, it records copy mode, pack ID,
   copy slot, template ID, prompt version, hook, CTA, and Instagram objective.
   Tagged destinations retain their existing campaign/creative `utm_content` and
   append the pack ID, selected copy slot, and template ID, so GA4 can
   distinguish a TikTok video template from article-carousel copy even when
   both promote an article. Insights snapshots and reports carry copy
   attribution without changing sample thresholds or winner selection.
   Instagram and TikTok bio-link destinations are not per-post clickable links;
   their UTM values only measure traffic when those destinations are actually
   exposed and clicked.

No per-post approval step is used. The scheduled workflow opens the promotion
PR automatically; manual dispatch defaults to generation without promotion.
The existing publisher controls, deduplication, browser confirmation, and
platform readiness checks remain in force.

## Channel coverage

| Channel | Integrated formats | Existing delivery path |
|---|---|---|
| Instagram | daily article/job carousels, weekly border carousel, scheduled Reels | Graph API or the existing Playwright robot and queue |
| TikTok | daily article/job carousels and weekly border content | TikTok Content Posting API or the existing Playwright robot and queue |
| Facebook | articles, events/digests, scheduled jobs | existing Graph API schedulers |
| LinkedIn | member-profile article/job posts and Company Page article path | member token and Posts API; Company Page permission currently denied |
| Telegram | daily jobs and weekly border digest | existing Bot API |
| Reddit | not included in this copy pack | existing readiness path; classic Data API is `path-refused`, Devvit has its own review path |

The generator does not enable new posting routes. The LinkedIn Company Page
path consumes the shared LinkedIn article copy when its existing publisher is
invoked, but its permission is currently denied. Reddit remains excluded from
the pack because Reddit's classic Data API request was refused; its next step
is a separate Devvit review. LinkedIn needs the Company Page permission grant
before that publisher can deliver. TikTok's unaudited Content Posting API
may publish only to the owner; public visibility still depends on TikTok's
audit. Instagram API permissions remain governed by Meta App Review and the
current readiness probe. The existing `SOCIAL_ROBOT_MODE` and publisher
credentials stay in their existing publisher/robot processes; this change
neither exposes them to Codex nor changes the mode. The upstream skill itself
warns that browser-based posting may violate Instagram's Terms, so its
copy-only design is not treated as authorization for a new browser route. No
post-volume increase is part of this change. The scheduled Facebook
jobs workflow continues to request 24 posts per day; its manual dispatch
retains its existing configurable volume.

After this PR is merged, rollout requires one run of
`gh workflow run social-copy-pack.yml --ref main -f promote=true`. That run
generates the initial pack and opens a separate protected data PR; until that
PR passes the required checks and merges, deterministic copy remains active.

## Editorial and measurement rules

- Keep factual claims in publisher-rendered content sourced from the site's
  verified dataset. AI contributes only short hooks and CTAs.
- Conversation CTAs may ask one substantive open question in comments. Do not
  ask for a keyword DM or promise a follow-up the active worker cannot deliver.
- Keep Instagram's current 24-hour diagnostic and 72-hour decision windows,
  minimum observations, exploration share, and lift thresholds. Copy metadata
  is added to reports without lowering a gate or treating insufficient data as
  a winner.
- Firebase remains the control plane for experiments and assignment. This copy
  pack is one deterministic editorial layer, not a new experiment flag.
- Native performance data in the current feedback loop comes from Instagram
  Insights only. GA4 can describe sessions and on-site engagement that arrive
  through clickable, tagged destinations; it does not measure reach or post
  engagement on Facebook, TikTok, LinkedIn, or Telegram. Instagram and TikTok bio links also need to
  expose the matching destination before GA4 can attribute a post-level click.
  This is a copy integration and attribution foundation, not yet a complete
  cross-network growth optimizer.
- Codex receives no publishing token or persistent browser session. The
  publisher and robot keep their existing credential boundaries.
- GA4 feedback covers only sessions that arrive through a tagged, clickable
  destination. The initial live query returned no copy-attributed rows; later
  monthly briefs must treat unavailable or absent rows as missing evidence, not
  as zero traffic or poor performance.

## Growth work beyond this copy integration

This first phase gives the existing posts platform-specific copy and joins
some downstream sessions to a copy slot. It does not yet compare native reach
or engagement across all platforms, control the Instagram/TikTok bio link per
post, add new formats, or change publishing volume. Those are the inputs needed
before Codex can optimize cross-network growth instead of only learning from
Instagram and clickable-site traffic.

| Priority | Next work | Dependency |
|---|---|---|
| 1 | Capture native post-level reach, views, saves, shares, and replies for Facebook, TikTok, LinkedIn, and Telegram; keep each platform's minimum sample and date window explicit. | Read access to each platform's analytics and a stable post-ID ledger. |
| 2 | Add a branded, per-post landing route for Instagram and TikTok bio links so clicks can identify the post without claiming ordinary caption links are clickable. | Profile-link update path and stable canonical redirects. |
| 3 | Compare format and copy performance before expanding cadence or adding formats; use the existing Firebase experiment control plane for any controlled variant test. | Enough native observations; no new PostHog experiments. |
| 4 | Bring Reddit into the copy pack after its replacement publishing path is approved. The LinkedIn Company Page already reuses LinkedIn article copy when invoked. | Devvit review for Reddit; Company Page permission grant remains needed for LinkedIn delivery. |

No platform's external review, audience setting, or rate limit is overridden by
the owner's authorization or by Codex.

The generation input and pack contain no comments, DMs, usernames, private
conversation text, or credentials. For source attribution and the upstream
skill's pinned revision, see docs/third-party/instagram-agent-skill/UPSTREAM.md.
