# ─── One shared group for every crawler we welcome ───────────────────────
# RFC 9309 §2.2.1: a crawler obeys ONLY the most specific group that names it
# and then ignores `User-agent: *`. Until 2026-10 every welcomed bot had its own
# `User-agent: X` + `Allow: /` group, which silently cancelled every Disallow
# written for `*` (`/cerca-lavoro-ticino/?q=infermiere` was crawlable by
# Googlebot, Bingbot, GPTBot, ClaudeBot…). So every welcomed agent is a
# `User-agent:` line of THIS group and shares its rules. To welcome a new bot,
# add a `User-agent:` line here — never a separate `Allow: /` group — and keep
# the group free of blank lines. Guarded by tests/robots-txt-groups.test.ts.
User-agent: *

# ─── Sitemaps ─────────────────────────────────────────────────────────────
# `Sitemap:` is a non-group record (RFC 9309 §2.2.4): it applies to the whole
# file wherever it sits. No `Host:` line: it is a Yandex-only extension that
# Google and Bing ignore; the www → non-www canonical host is enforced by the
# edge 301, not here.
#
# The index enumerates every sub-sitemap (pages, blog, glossario, jobs, guides,
# and 60+ other template families) — those are NOT listed individually here:
# crawlers follow the index fine, and a hand-maintained per-shard list drifts
# stale as new template families ship (issue #4413 — the list had 7 lines vs 73
# sub-sitemaps in the actual index). sitemap-news.xml stays explicit: Google
# News discovery is a separate mechanism from regular sitemap-index crawling
# and expects its own `Sitemap:` line (see tests/sitemap-news-canonical.test.ts,
# "A4 Google News compliance" — do not remove without updating that test's
# requirement too).
Sitemap: https://frontaliereticino.ch/sitemap.xml
Sitemap: https://frontaliereticino.ch/sitemap-news.xml
