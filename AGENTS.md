Il deferral come meccanismo di chiusura è **ABOLITO**: `## Non implementato` non è più un permesso di fermarsi, è un **piano di completamento tracciato** che tiene il task **APERTO**. Finché contiene scope reale, l'agente **PROSEGUE** (stessa PR quando possibile — vedi single-bundle — o PR concatenate sullo stesso task) fino a portarlo live; non chiude il turno dichiarando «fatto» con residuo aperto. «Out of scope» NON è più una scappatoia: se un lavoro è correlato/necessario va fatto; se è davvero un task diverso e scorrelato **non va elencato qui** (apri un task separato), ma se lo elenchi ti impegna. Gli stati letterali che chiudono legittimamente una voce sono CINQUE — gli stessi che riconoscono le macchine (`STATE_PATTERNS` in `scripts/lib/pr-body-sections-check.mjs`, da cui `scripts/ci/followup-has-candidates.mjs` importa `bulletState()`): `in questa PR`, `PR concatenata #N`, `blocked: <causa>`, `per scelta`, `by construction`. `per scelta` e `by construction` sono un **no motivato**, non un rinvio — chiudono la voce (non la tengono aperta) — ma valgono **SOLO se il bullet porta anche il motivo scritto**: un bullet che dice soltanto «per scelta» o soltanto «by construction», senza spiegare perché, resta bocciato esattamente come uno che dice solo «fuori scope» — è la stessa scappatoia con un nome nuovo. Unica voce che tiene il task aperto-non-chiudibile senza colpa: `blocked` con causa esterna reale e dichiarata (l'agente prima tenta di **rimuovere il blocco** — vedi `## Build And Test → Blocker ≠ stallo` — e solo se impossibile lo lascia, task **non chiuso**). Reviewer: scope-feature residuo senza essere fatto né piano-di-completamento esplicito, o `per scelta`/`by construction` senza motivo = 🔴 (vedi `REVIEW.md`).

## Workflow

- Worktree-first obbligatorio per task che edita/committa/pusha. Local `main` checkout = shared/read-only (status/inspection).
- **Base worktree = `origin/main`, MAI il local `main` checkout.** Sempre `git fetch origin main` poi `git worktree add -b <branch> <path> origin/main`. Il local `main` può essere **centinaia di commit dietro** e con working tree sporco di **foreign work** (`data/jobs/*.json` stale): branchare da lì = base vecchia + rischio di committare il dirty. Branchare da `origin/main` parte fresh senza toccare il local `main`.
- Mai edit/stage/stash/restore/commit/rebase/merge sul local `main` salvo richiesta esplicita user. File dirty su `main` = lavoro foreign, intoccabile — verità è `origin/main` (`git show origin/main:<file>`, non il checkout locale). Sync stale+dirty local `main` (solo su richiesta esplicita user) → runbook `docs/LOCAL-DEV.md#syncing-a-stale-dirty-local-main-explicit-user-request-only`.
- Parallel/subagent → sempre worktree isolati, mai shared dir.
- Auto commit+push task successful. PR-as-merge-vehicle: create PR, squash merge, delete remote branch, remove worktree.
- `delete_branch_on_merge: true` attivo (2026-05-29): GitHub **cancella in automatico il branch remoto a OGNI merge**, non solo con `--delete-branch`. Scatta solo sul merge (chiusura-senza-merge coperta da `worktree-branch-janitor.yml`, job `delete-closed-unmerged`, cron rete-sicurezza ≤24h). Branch **locale** + **worktree** restano a carico dell'agent: rimuovili nello stesso turn del merge. Audit: `git branch -r` deve mostrare solo `main` + PR realmente aperte. Dettaglio: `docs/AGENTS-HISTORY.md#branch-cleanup`.
- PR body OBBLIGATORIO con `## Implementato` + `## Non implementato (ancora)`. Reviewer automatico legge per gating. Vedi `REVIEW.md`. **Semantica post-#8: `## Non implementato (ancora)` è il PIANO DI COMPLETAMENTO del task ancora aperto**, non scope-deferito-e-chiuso — ogni voce indica **stato e next step** (`in questa PR` / `PR concatenata #N` / `blocked: <causa esterna reale>`), mai bullet vuoto o placeholder `TBD`/`N/A`. **Il task è chiuso SOLO quando questa sezione legge «Nessuno»** (Non-Negotiable #8). `pr-body-contract.yml` valida solo la PRESENZA degli header, non il contenuto: verifica tu con `git diff origin/main` prima di `gh pr create` che ogni bullet in `## Implementato` corrisponda a una modifica reale nel diff. Dettaglio: `docs/AGENTS-HISTORY.md#pr-body-contract`.
- Se la PR rende **moot/obsoleta** una issue aperta → dichiaralo nel body: `Closes #N` (chiude al merge) o `Supersedes #N` (link, non chiude). Solo `Closes #N` esplicito chiude — niente issue orfane.
  - **Due meccanismi distinti.** `closingIssuesReferences` (`gh pr view <N> --json closingIssuesReferences`) = preview del body PR corrente, non l'azione reale. La chiusura VERA legge il `squash_merge_commit_message` (`gh api repos/<owner>/<repo> --jq '.squash_merge_commit_message'`) = concatenazione dei commit del branch, NON il body PR. Editare solo il body può non bastare se la keyword non è mai stata in un commit. Prima di dichiarare completo: verifica `closingIssuesReferences`, riporta quale issue chiudi. Dettaglio/incidente: `docs/AGENTS-HISTORY.md#closes-must-be-in-pr-body`.
  - **MAI** scrivere `Closes`/`Fixes`/`Resolves`+`#N` in un commit message adiacente a un'issue reale, nemmeno come narrativa storica — finisce nel commit di merge e GitHub la esegue alla lettera. Riferimento storico a un'issue: numero senza `#` (es. "issue 3485"), mai adiacente a keyword di chiusura.
  - **Multi-issue: una keyword per issue, una per riga** — `Closes #a #b #c` chiude solo `#a`. Scrivi `Closes #a` / `Closes #b` su righe separate. Gate `pr-body-contract.yml` + reviewer flaggano la violazione. Dettaglio: `docs/AGENTS-HISTORY.md#multi-issue-close`.

Gating: `## LGTM` → auto-merge; `🔴 Important` o 🔴 process "missing sections" → no auto-merge, agent applica fix in nuovo commit sullo stesso branch (re-review automatica). Dopo open/update di una PR **non chiudere il turno finché non è risolta** — poll BREVE ricorrente (`gh pr view <N> --json state,reviews` ogni ~30-60s) fino a stato terminale (`MERGED` / `## LGTM` / `🔴 Important`), **posta status a ogni cambio**. ## Post-merge feedback handling

- Reviewer bot posta 🔴/🟡/❓ in review body. **Mai silent ignore di 🟡/❓.** Workflow `post-merge-followup.yml` triagia automaticamente post-merge: legge PR body `## Non implementato` + reviewer 🟡/❓/adversarial-check, applica filtro scopo (`REVIEW.md`), crea issue `follow-up` + summary commento sulla PR. Contratto in `FOLLOWUP.md`.
- 🔴 Important blocca merge (auto-merge richiede `## LGTM`). Se compare 🔴 → fix in nuovo commit sullo stesso branch, re-review automatica.
- Agent inizio task DEVE controllare `gh issue list --label follow-up --state open` se tocca area correlata. Issue follow-up esistente per scope corrente → linkare nel PR body (`## Implementato` chiude issue con `Closes #N`) o aggiornare l'issue con rationale.
- Test plan PR body con `- [ ]` non spuntate post-merge → spunta dopo verifica live, oppure converti in issue follow-up. Reviewer flagga come 🟡 quelle non verificabili pre-merge (vedi `REVIEW.md → "Test plan compliance"`).
- Eccezione drop senza issue: nit puro stilistico-deferibile (non funnel) → reply inline sulla PR review thread con motivo "deferred — non funnel-critical". `post-merge-followup.yml` lo include automaticamente nella sezione "Dropped" del summary.

## Issue automation (loop autonomo)

- Pipeline: monitor → issue → `issue-triage` (classify+route **deterministico, no Claude**; applica `agent:fix` via `GITHUB_PAT` da RC) → `issue-fix` (fix→PR) → `pr-review-loop` (`## LGTM`) → `auto-merge-on-lgtm` (merge via PAT) → deploy → `post-merge-followup` (batch 1 issue/PR). Contratto completo in `ISSUES.md` / `FOLLOWUP.md`.
- **Auto-route consentito su OGNI categoria** (2026-07-05, owner decision "Rimuovi tutte le guardie"): `crawler` → `agent:fix` immediato (production-critical, route diretto sicuro), **al più uno per run e solo a slot `issue-fix` libero** — l'eccedenza in coda ad alta priorità, e una run crawler cancellata viene ri-armata dal drainer (#5514); ogni altra categoria (`revenue`/`tracker`/`validation-failure`/`follow-up`/`other`) → `agent:fix-queued`, drenata UNA alla volta da `followup-drainer` (anti-starvation, vedi `ISSUES.md`). Nessuna categoria è più opt-in-manuale: supervisione umana = gate `## LGTM` del reviewer PR, non esclusione a monte dal routing. `/fix-issue` locale resta disponibile per intervenire a mano prima della coda.
- **Claim mutex `agent:in-progress`** (#4788/#4793: una sessione locale + `issue-fix.yml` hanno fixato la stessa issue in parallelo → due PR in conflitto): `crawler` scatta `agent:fix` immediato senza attesa in coda, quindi una sessione interattiva che parte sulla stessa issue ha una finestra di collisione reale, non ipotetica. `issue-fix.yml` reclama la label come PRIMO pre-flight step (prima del tier), zero-Claude; `/fix-issue` locale la reclama come primo passo del Bootstrap (Pre-condizioni, `ISSUES.md` Appendice A). Chi arriva prima vince, l'altro vede la label già presente e si ferma prima di spendere turni. Rilascio simmetrico a fine lavoro/abbandono da entrambi i lati — mai lasciarla stale.
- **Dedup a MONTE, non nel triage**: i monitor non devono aprire issue duplicate. Usa `scripts/lib/github-issue-creator.mjs` con **titolo stabile** (no run-number/timestamp nei primi 60 char) → dedupa e commenta sull'issue canonica. I follow-up: 1 issue aggregata/PR (`post-merge-followup` / `FOLLOWUP.md`, #925).
- **Handoff triage→fix richiede PAT**: una label `agent:fix` via `GITHUB_TOKEN` NON triggera `issue-fix` (anti-ricorsione GitHub) e ha sender `github-actions[bot]` che non passa il gate. Stesso vincolo del cascade merge→deploy (#844/#880). I workflow che devono triggerarne altri caricano `GITHUB_PAT` via `scripts/load-rc-env.mjs` (serve Firebase SA).

CI test gate: `npm ci`, `node scripts/assemble-jobs-dataset.mjs --stats`, `node scripts/migrate-all-known-job-slugs-canton-aware.mjs`, `npm test`.

- **Review gateata su test-verdi**: `pr-review-loop` triggera su `workflow_run[tests]==success`, mai su `pull_request` — porta i test a verde PRIMA di `gh pr create`. Mai aprire PR con vitest rosso. Dettaglio: `docs/AGENTS-HISTORY.md#test-verdi-gate`.
- **Pre-PR si girano i test IMPATTATI dal diff, non la suite intera** — stessa politica del gate CI, che dal `tests.yml` seleziona con `scripts/ci/run-related-tests.mjs` invece di pagare il costo pieno. Ricetta locale, dalla root del worktree:
  ```bash
  git fetch origin main -q
  git diff --name-only origin/main > changed-paths.txt   # senza punti: confronto contro il WORKING TREE
  printf 'complete\n' > changed-paths-status.txt
  node scripts/ci/run-related-tests.mjs
  ```
  `origin/main` **senza punti**, non `origin/main..HEAD` né `origin/main...HEAD`: senza punti git confronta il ref col **working tree**, quindi vede anche le modifiche non ancora committate — cioè esattamente il caso in cui stai per girare i test. Le due forme con i punti confrontano commit contro commit e le perdono. Il runner cammina a ritroso un grafo di import statici dai file cambiati, include sempre i test cambiati, e ricade sulla suite intera solo quando non riesce a provare che il diff è completo — quindi «nessun test selezionato» è un'informazione, non un permesso di saltare il gate. `changed-paths.txt` e `changed-paths-status.txt` sono input del runner e sono gitignorati.
  In un worktree sparse il runner stampa `N tracked file(s) unreadable … the selection may be incomplete`: è atteso e non è un guasto — sono i symlink verso path esclusi dal profilo, per esempio `services/blogArticleIds.ts` → `packages/articles/content/`. Leggi il numero: se cresce di colpo, il profilo sparse sta escludendo qualcosa che ti serve.
- **La suite intera NON è l'oracolo pre-PR in un worktree sparse.** Misurato il 2026-09-04 su `wf17`: 32.963 test, **156 rossi su 168 file**, nessuno dei quali toccato dal diff — test di componenti, i18n, router e consenso che falliscono per `public/`/`data/` assenti o per rete verso host finti (`navigation failed for https://acme.test/jobs`). Un rosso ereditato non si distingue da uno proprio senza un secondo worktree su `origin/main` che rifaccia la stessa corsa, che è mezz'ora spesa per una risposta che il gate CI dà meglio. Girala per intero (`node scripts/assemble-jobs-dataset.mjs && npm test`, serve `onnxruntime-node`) solo quando serve davvero la copertura completa, e allora **con** il controllo su `origin/main`: senza, il verdetto non significa niente.
- **Test fixture: mai date assolute.** Pipeline stale-prune (`cleanup-jobs.mjs`, soglia 60gg) → `crawledAt`/`datePosted` relativi a now (`daysAgo(n)`), mai literal (`'2026-04-01'`) — date hardcoded = time-bomb calendario. Dettaglio/incidente: `docs/AGENTS-HISTORY.md#test-fixture-relative-dates`.
- **main rosso blocca a cascata**: `auto-merge-on-lgtm` fira su `## LGTM` senza attendere vitest — il vitest-red su `main` resta e ogni branch lo eredita finché non fa `merge origin/main`. Priorità assoluta: `main` verde; se rosso, fixa root cause prima di ogni altro lavoro pipeline.
- **Blocker ≠ stallo: rimuovi il blocco, non solo segnalarlo.** PR non auto-mergia per gate rosso → NON fermarti a «apro issue + riporto bloccato», una PR ferma non consegna niente (vale anche per `/goal` autonomi). Stesso principio su Non-Negotiable #8: scope residuo in `## Non implementato` ≠ task chiuso — prosegui (PR concatenata) finché non legge «Nessuno». Prima di «fuori scope» DEVI: (a) cercare un fix già esistente (`git log`/PR/issue recenti — spesso già risolto: `merge origin/main` + ri-esegui il gate); (b) stimare il costo reale indagando la pipeline, non assumere; (c) confermare che tocca davvero un dominio che non puoi/devi cambiare. Solo allora «fuori scope» è lecito. Dettaglio/incidente: `docs/AGENTS-HISTORY.md#blocker-not-stall`.
- **Data-refresh che committa su `main` = stesso gate test di una PR.** Workflow bot-direct-to-main (es. `sync-gsc-orphans`, `discover-404s` → `data/seo-404-compat-paths.json`) DEVE validare l'invariante impattato PRIMA del commit — pattern: `scripts/prune-404-compat-paths.ts` droppa pre-commit i path che `resolveSearchConsoleCompatTarget` non mappa, `tests/search-console-compat.test.ts` resta verde. Mai committare dump grezzo non validato; cap ragionevole sul file. Dettaglio/incidente: `docs/AGENTS-HISTORY.md#data-refresh-gate`.
- **Claim build/perf/memoria non validabile pre-merge → dichiara il trigger di revert in `## Non implementato`.** Path SSG-emit memory (`build-plugins/jobsSeoPagesPlugin.ts`, `build-plugins/shared/seoPageShell.ts`, worker pool, `POST_WALK_WORKERS`) e claim wall-time NON verificabili su `pull_request` (`build:ci` OOM-prone gira solo post-merge). Niente claim verde fabbricato: o allega un run misurato (mem-curve `[mem]` log / wall-time Actions), o dichiara il revert-trigger esplicito ("se il prossimo deploy OOMa/regredisce → revert"). Senza, è 🔴. Dettaglio/incidente: `docs/AGENTS-HISTORY.md#unvalidated-perf-claim`.

## Architecture

- React 19 + TypeScript + Vite + Tailwind.
- No React Router. Routing hand-rolled in `services/router.ts`; `App.tsx` owns navigation state.
- Canonical prod domain: `https://frontaliereticino.ch` (no `www`).
- **Trailing slash obbligatorio su OGNI nuovo link/route/URL.** Convenzione canonica del sito: `buildPath()` (`finish()` in `services/router.ts`) e `joinPath()` (`build-plugins/weeklyEmployersData.ts`) lo forzano già; canonical/sitemap/og:url lo usano; la zone redirect rule `trailing-slash-301` (gestita da `scripts/cf-locale-failover-setup.mjs`, #3472) 301-redirecta no-slash→slash all'edge. Mai hardcodare URL senza slash finale (es. in email/CF/script/`trackPageView`) — preferisci `buildPath({activeTab:...}, locale)` invece di stringhe a mano (slash by-construction). Un href/URL letterale senza slash = doppione non-canonico. Pre-PR: grep dei nuovi `href=`/URL string nel diff → verifica lo slash.
- Primary locale Italian; EN/DE/FR via chunked locale files in `services/locales/`.
- Nav caps: 6 top-level tabs, 8 sub-tabs/category.
