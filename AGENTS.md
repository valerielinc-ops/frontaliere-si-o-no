8. **Definizione di «fatto» = completezza totale, NON merge della prima PR.** Un task/funzionalità si ritiene **chiuso SOLO quando `## Non implementato (ancora)` legge «Nessuno»** — cioè quando *tutto* lo scope elencato è implementato e **live**, inclusi gli item che prima si etichettavano `out of scope` / `posposto` / `follow-up`. Il deferral come meccanismo di chiusura è **ABOLITO**: `## Non implementato` non è più un permesso di fermarsi, è un **piano di completamento tracciato** che tiene il task **APERTO**. Finché contiene scope reale, l'agente **PROSEGUE** (stessa PR quando possibile — vedi single-bundle — o PR concatenate sullo stesso task) fino a portarlo live; non chiude il turno dichiarando «fatto» con residuo aperto. «Out of scope» NON è più una scappatoia: se un lavoro è correlato/necessario va fatto; se è davvero un task diverso e scorrelato **non va elencato qui** (apri un task separato), ma se lo elenchi ti impegna. Unica voce che tiene il task aperto-non-chiudibile senza colpa: `blocked` con causa esterna reale e dichiarata (l'agente prima tenta di **rimuovere il blocco** — vedi `## Build And Test → Blocker ≠ stallo` — e solo se impossibile lo lascia, task **non chiuso**). Reviewer: scope-feature residuo senza essere fatto né piano-di-completamento esplicito = 🔴 (vedi `REVIEW.md`).

## Workflow

- Worktree-first obbligatorio per task che edita/committa/pusha. Local `main` checkout = shared/read-only (status/inspection).
- **Base worktree = `origin/main`, MAI il local `main` checkout.** Sempre `git fetch origin main` poi `git worktree add -b <branch> <path> origin/main`. Il local `main` può essere **centinaia di commit dietro** e con working tree sporco di **foreign work** (`data/jobs/*.json` stale): branchare da lì = base vecchia + rischio di committare il dirty. Branchare da `origin/main` parte fresh senza toccare il local `main`.
- Mai edit/stage/stash/restore/commit/rebase/merge sul local `main` salvo richiesta esplicita user. File dirty su `main` = lavoro foreign, intoccabile — verità è `origin/main` (`git show origin/main:<file>`, non il checkout locale). Se l'user chiede esplicito di sincronizzare un local `main` stale+dirty: `git stash push -u` (backup) → `git reset --hard origin/main`; se fallisce con `Entry '...' not uptodate` ma `git status` è clean = racy-index (~19k file) → fix canonico `rm -f .git/index && git reset --hard HEAD`. NON committare mai il dirty.
- Parallel/subagent → sempre worktree isolati, mai shared dir.
- Auto commit+push task successful. PR-as-merge-vehicle: create PR, squash merge, delete remote branch, remove worktree.
- `delete_branch_on_merge: true` attivo (2026-05-29): GitHub **cancella in automatico il branch remoto a OGNI merge**, non solo con `--delete-branch`. Scatta solo sul merge (chiusura-senza-merge coperta da `worktree-branch-janitor.yml`, job `delete-closed-unmerged`, cron rete-sicurezza ≤24h). Branch **locale** + **worktree** restano a carico dell'agent: rimuovili nello stesso turn del merge. Audit: `git branch -r` deve mostrare solo `main` + PR realmente aperte. Dettaglio: `docs/AGENTS-HISTORY.md#branch-cleanup`.
- PR body OBBLIGATORIO con `## Implementato` + `## Non implementato (ancora)`. Reviewer automatico legge per gating. Vedi `REVIEW.md`. **Semantica post-#8: `## Non implementato (ancora)` è il PIANO DI COMPLETAMENTO del task ancora aperto**, non scope-deferito-e-chiuso — ogni voce indica **stato e next step** (`in questa PR` / `PR concatenata #N` / `blocked: <causa esterna reale>`), mai bullet vuoto o placeholder `TBD`/`N/A`. **Il task è chiuso SOLO quando questa sezione legge «Nessuno»** (Non-Negotiable #8). `pr-body-contract.yml` valida solo la PRESENZA degli header, non il contenuto: verifica tu con `git diff origin/main` prima di `gh pr create` che ogni bullet in `## Implementato` corrisponda a una modifica reale nel diff. Dettaglio: `docs/AGENTS-HISTORY.md#pr-body-contract`.
- Se la PR rende **moot/obsoleta** una issue aperta → DEVE dichiararlo nel body: `Closes #N` (scope interamente coperto, chiude al merge) oppure `Supersedes #N` (link senza chiudere, solo parziale). `post-merge-followup.yml` segnala le issue `follow-up` correlate ma non chiude su euristica — solo `Closes #N` esplicito chiude. Niente issue orfane.
  - **Due meccanismi DISTINTI, non confonderli.** (1) `closingIssuesReferences` (`gh pr view <N> --json closingIssuesReferences`) riflette SOLO il body della PR corrente — preview/verifica, non l'azione reale. (2) La chiusura VERA a merge legge il commit di merge su `main`; `squash_merge_commit_message` è `COMMIT_MESSAGES` (`gh api repos/<owner>/<repo> --jq '.squash_merge_commit_message'`) → quel commit è la CONCATENAZIONE dei commit message del branch (squash), NON il body PR. Quindi: (a) editare solo il body via `gh pr edit` soddisfa (1) ma può NON bastare per (2) se la keyword non è MAI stata in un commit del branch; (b) prima di dichiarare il task completo verifica `closingIssuesReferences` come segnale minimo, e riporta quale issue si sta chiudendo.
  - **MAI scrivere un pattern-di-chiusura (`Closes`/`Fixes`/`Resolves` + `#<numero>`) in un commit message adiacente a un'issue reale, nemmeno come narrativa/storica di un incidente passato.** Dato (2) sopra, quel testo finisce nel commit di merge su `main` a prescindere dal body PR e GitHub lo esegue alla lettera. Incidente jul05: PR #3568 narrò l'incidente su issue 3485 → al merge GitHub la chiuse DAVVERO mentre il fix reale (#3562) era ancora OPEN. Per riferimenti storici a un'issue in un commit message: scrivi il numero senza `#` (es. "issue 3485"), mai adiacente a una keyword di chiusura. Dettaglio: `docs/AGENTS-HISTORY.md#closes-must-be-in-pr-body`.
  - **Multi-issue: UNA keyword per issue, UNA per riga.** GitHub chiude SOLO la prima issue dopo una keyword di chiusura (`Closes`/`Fixes`/`Resolves`) — `Closes #a #b #c` su una riga chiude solo `#a`. Scrivi sempre `Closes #a` / `Closes #b` su righe separate (o ripeti la keyword inline). Gate deterministico `pr-body-contract.yml` + reviewer flaggano la violazione. Dettaglio: `docs/AGENTS-HISTORY.md#multi-issue-close`.

## Post-merge feedback handling

- Reviewer bot posta 🔴/🟡/❓ in review body. **Mai silent ignore di 🟡/❓.** Workflow `post-merge-followup.yml` triagia automaticamente post-merge: legge PR body `## Non implementato` + reviewer 🟡/❓/adversarial-check, applica filtro scopo (`REVIEW.md`), crea issue `follow-up` + summary commento sulla PR. Contratto in `FOLLOWUP.md`.
- 🔴 Important blocca merge (auto-merge richiede `## LGTM`). Se compare 🔴 → fix in nuovo commit sullo stesso branch, re-review automatica.
- Agent inizio task DEVE controllare `gh issue list --label follow-up --state open` se tocca area correlata. Issue follow-up esistente per scope corrente → linkare nel PR body (`## Implementato` chiude issue con `Closes #N`) o aggiornare l'issue con rationale.
- Test plan PR body con `- [ ]` non spuntate post-merge → spunta dopo verifica live, oppure converti in issue follow-up. Reviewer flagga come 🟡 quelle non verificabili pre-merge (vedi `REVIEW.md → "Test plan compliance"`).
- Eccezione drop senza issue: nit puro stilistico-deferibile (non funnel) → reply inline sulla PR review thread con motivo "deferred — non funnel-critical". `post-merge-followup.yml` lo include automaticamente nella sezione "Dropped" del summary.

Pattern: prune dei record invalidi pre-commit (`scripts/prune-404-compat-paths.ts` droppa i path che `resolveSearchConsoleCompatTarget` non mappa → `tests/search-console-compat.test.ts` resta verde). Senza gate, un commit `github-actions[bot]` non presidiato manda main rosso senza PR colpevole (outage 2026-06-02). Mai committare dump grezzo non validato; cap ragionevole sul file (anti-bloat).
- **Claim build/perf/memoria non validabile pre-merge → dichiara il trigger di revert in `## Non implementato`.** I path SSG-emit memory (`build-plugins/jobsSeoPagesPlugin.ts`, `build-plugins/shared/seoPageShell.ts`, worker pool, `POST_WALK_WORKERS`) e i claim wall-time NON sono verificabili sul `pull_request` (il `build:ci` OOM-prone gira solo post-merge su `main`). Mergiare un claim "atteso GREEN/−NNN MB" speculativo brucia un ciclo deploy 30-90min se regredisce (pattern #795/#802 → revert #822; REVIEW.md step 7 lo flagga, PR #1185–1311). Regola: niente claim verde fabbricato; o alleghi un run misurato (mem-curve dai `[mem]` log / wall-time da Actions), o scrivi in `## Non implementato` il revert-trigger esplicito ("se il prossimo deploy OOMa o wall-time regredisce → revert"). Il reviewer accetta il claim non validato SOLO con questa dichiarazione; senza, è 🔴.

## Architecture

- React 19 + TypeScript + Vite + Tailwind.
- No React Router. Routing hand-rolled in `services/router.ts`; `App.tsx` owns navigation state.
- Canonical prod domain: `https://frontaliereticino.ch` (no `www`).
- **Trailing slash obbligatorio su OGNI nuovo link/route/URL.** Convenzione canonica del sito: `buildPath()` (`finish()` in `services/router.ts`) e `joinPath()` (`build-plugins/weeklyEmployersData.ts`) lo forzano già; canonical/sitemap/og:url lo usano; la zone redirect rule `trailing-slash-301` (gestita da `scripts/cf-locale-failover-setup.mjs`, #3472) 301-redirecta no-slash→slash all'edge. Mai hardcodare URL senza slash finale (es. in email/CF/script/`trackPageView`) — preferisci `buildPath({activeTab:...}, locale)` invece di stringhe a mano (slash by-construction). Un href/URL letterale senza slash = doppione non-canonico. Pre-PR: grep dei nuovi `href=`/URL string nel diff → verifica lo slash.
- Primary locale Italian; EN/DE/FR via chunked locale files in `services/locales/`.
- Nav caps: 6 top-level tabs, 8 sub-tabs/category.

## Static SEO Pages

- Static SSG page emit via build plugin DEVE usare `build-plugins/shared/seoPageShell.ts` → `buildSeoPageHtml`.
- Static plugin contract: `apply: 'build'`, `enforce: 'post'`, emit in `closeBundle()`, pass `distDir`.
- **Ogni loop SSG canton-scoped con floor/soglia** (`continue` su below-floor/zero-match) DEVE, nella STESSA PR: (1) emettere una bridge page `noindex,follow` alla stessa URL invece di skip silenzioso (pattern `renderBelowFloorBridge`/`emitEditorialBelowFloorBridge`/`emitCantonHubBelowFloorBridge`, PR #3594); (2) aggiungere il self-map corrispondente in `build-plugins/searchConsoleCompat.ts:resolveSearchConsoleCompatTarget` (stesso modello `isProfessionCantonPath`), altrimenti un vecchio snapshot 404 GSC resta droppato come non-risolvibile anche se la pagina è live. Nuovo self-map lì → precompila gli slug ammessi in un `Set` a module-load (mai chiamare risolutori che ricostruiscono Set per-chiamata dentro il loop principale: rompe `tests/search-console-compat.test.ts` su 150k+ path). Dettaglio/incidente: `docs/AGENTS-HISTORY.md#below-floor-bridge-self-map`. **Gate deterministico** (issue #3659, la regola prosa ricorreva ×6/14gg): `scripts/ci/check-below-floor-bridge.mjs`, wired ADVISORY in `pr-body-contract.yml`, surfaca `continue` su guard floor/soglia senza bridge-call E nuovo bridge senza tocco a `searchConsoleCompat.ts`. Heuristico (regex, non AST) — candidato ≠ verdetto.
- Body styling HTML statico: Tailwind utilities only. `tailwind.config.js` content DEVE includere `./build-plugins/**/*.{js,ts}`.
- SPA/static handoff = router-driven via `staticOverlay`; mai reintrodurre DOM heuristic per `main.seo-static-content`.
- Mobile-first: real content subito dopo H1/tagline. Long intro/methodology/FAQ sotto action/data area o in accordion collassati.
- SEO landing order: breadcrumb, header con one-line lede ≤120 chars, 3-5 stat tile, advice banner se utile, primary CTA, data area, prose lunga.
- Solo semantic color token esistenti; no inline hex.
- Crawler dedicati: merge job by stable id `extractStableJobId(job.url)`, preserva previous slug, truncate via `truncateSlugAtWordBoundary`.
- SEO landing moratorium **RIMOSSO** (owner 2026-06-24): nuove SEO landing (build-plugin) sono consentite. La posizione media 7-day GSC (`data/gsc-position-rolling.json`) resta **tracciata** ma solo informativa — `scripts/check-seo-moratorium.mjs` è report-only (always exit 0) e lo step CI in `deploy.yml` è `continue-on-error`, mai bloccante.
